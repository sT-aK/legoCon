# LEGO Hub × Xbox Controller (Web Bluetooth)

純正ファームウェアのままの LEGO Powered Up ハブ（Technic Move Hub / Technic Hub / City Hub など）を、
**Xbox ワイヤレスコントローラー**で操作するための 1 ファイル完結の Web ページです。

ハブの改造もアプリのインストール（ブラウザを除く）も不要で、`index.html` を HTTPS で配信するだけで動きます。

- 実物: `index.html`（依存ライブラリなし・オフラインでも動作）
- 対象例: LEGO 42176 ポルシェ GT4 e-Performance（Technic Move Hub）

---

## 仕組み

```
[Xbox Wireless Controller]
      │  Bluetooth（iOS / iPadOS / Windows / macOS が標準対応）
      ▼
[iPhone など] ── Bluefy（iOS）または Chrome / Edge（PC）
      │  ├─ 1. Gamepad API  : トリガー・スティックの値を取得（0.0〜1.0 / -1.0〜1.0）
      │  └─ 2. LWP3         : LEGO Wireless Protocol v3 のバイナリコマンドを生成
      │  Web Bluetooth API（BLE / GATT）
      ▼
[LEGO Hub（純正・未改造）]
      ├─ 駆動モーター     : 出力（パワー）制御
      └─ ステアリング     : 目標角度制御
```

1. **Bluetooth 接続**: LEGO ハブ共通の BLE サービス UUID `00001623-1212-efde-1623-785feabcd123` で
   デバイスを絞り込み、キャラクタリスティック `...1624...` に対して読み書きします。
2. **制御ループ**: `requestAnimationFrame` で毎秒約 60 回コントローラーを読み取り、
   値が変化したときだけ LWP3 のコマンドを送信キューに積みます。

### 送信しているコマンド

| 用途 | LWP3 サブコマンド | バイト列 |
|---|---|---|
| 駆動モーター出力 | `WriteDirectModeData` (0x51) | `08 00 81 <port> 11 51 00 <power>` |
| ステアリング角度 | `GotoAbsolutePosition` (0x0D) | `0E 00 81 <port> 11 0D <angle:int32LE> <speed> <maxPower> 7E 00` |
| 角度の受信設定 | `Port Input Format Setup` | `0A 00 41 <port> 02 <delta:uint32LE> 01` |
| バッテリー通知 | `Hub Properties` | `05 00 01 06 02` |

## 使い方

### 1. Xbox コントローラーを接続する

iPhone / iPad の「設定」→「Bluetooth」からペアリングします。
Xbox のペアリングボタン（上面の小さなボタン）を長押しして、ロゴが速く点滅している状態で選択します。

### 2. ブラウザを用意する

| 環境 | ブラウザ |
|---|---|
| iPhone / iPad | **Bluefy – Web BLE Browser**（App Store・無料） |
| Windows / macOS / Android | Chrome または Edge |

> iOS の Safari と Chrome for iOS は Web Bluetooth に対応していないため動きません。Bluefy が必要です。

### 3. ページを公開する

Web Bluetooth は **HTTPS（または localhost）でしか動作しません**。
このリポジトリをそのまま GitHub Pages で公開するのが最短です。

1. GitHub の **Settings → Pages** を開く
2. **Source** を `Deploy from a branch`、ブランチを `main`（フォルダは `/root`）に設定
3. 数十秒後に `https://<ユーザー名>.github.io/<リポジトリ名>/` で公開されます

Netlify や Vercel にドラッグ&ドロップしても同じです。

### 4. 接続して走らせる

1. Bluefy で公開した URL を開く
2. コントローラーの**いずれかのボタンを 1 回押す**
   （ブラウザは最初の入力があるまでゲームパッドを認識しません。「検出」が緑になれば OK）
3. **タイヤを直進状態にしてから**、ハブの緑ボタンを 1 回押して**緑点滅**させる
4. ページの「LEGO Hub に接続」をタップし、ポップアップに出たハブを選択
5. 「ポート割り当て」で実際のモーター配置を確認（接続すると自動で検出結果が出ます）
6. 右トリガーで前進、左トリガーで後退、左スティックでステアリング

## このページの安全設計

模型とはいえモーターは指を挟むだけの力があり、暴走すると止められません。次の保護を入れてあります。

- **安全ロック**: 接続時にアクセルが握られたままなら、いったん離すまで出力しません。
- **緊急停止**: 画面の STOP ボタン、コントローラーの **B ボタン**、キーボードの **Space**。
- **自動停止**: ハブとの切断時、コントローラーの切断時、ページを閉じた・バックグラウンドに回った時。
- **ステアリングの端当て防止**: 既定の「角度指定」モードでは目標角へ動かす方式のため、
  メカストップにフルトルクで押し付け続けません。トルク上限も別途設定できます。
- **最大出力の制限**: 既定は 70%。慣れるまで下げておくのがおすすめです。

## 元のサンプルコードから変更した点

よく出回っている「60fps で `sendMotorPower()` を呼ぶだけ」の実装には、実機で困る問題がいくつかあります。

| 問題 | 起きること | このページでの対処 |
|---|---|---|
| BLE 書き込みを `await` せず並行実行 | `GATT operation already in progress` 例外が多発 | 送信キューで直列化。同じポートの古い指示は新しい値で上書き |
| 60fps でそのまま送信 | BLE の接続間隔を超えて詰まり、遅延・切断 | ポートごとに最短 35ms のレート制限 |
| ステアリングを生パワーで駆動 | 舵角の端でモーターが停動し続け、発熱・ギア破損 | `GotoAbsolutePosition` による角度制御 + トルク上限 |
| 「変化が 3 以上なら送る」判定 | トリガーを離しても 0 が送られず微速で走り続ける | 0 は必ず即時送信 |
| `writeValueWithoutResponse` 決め打ち | 非対応の特性で例外 | `properties` を見て `writeValue` に自動フォールバック |
| `gamepads[0]` 決め打ち | iOS では index が 0 とは限らず、null 穴もある | 接続中のパッドを走査して選択 |
| ボタン番号の決め打ち | 標準マッピングと認識されない環境ではトリガーが別の軸に出る | 実際に動かして割り当てを学習する機能 |
| 接続直後にすぐ GATT 操作 | `Connection already in progress` で全ての読み書きが失敗する | 接続後に待機し、一時エラーは再試行。機種 ID の応答で疎通を確認 |
| デッドゾーンなし | スティックのドリフトで直進しない | デッドゾーン + 感度カーブ（EXPO）を調整可能 |
| ポート番号がハードコード | 機種や組み方が違うと動かない | 接続時にモーターを自動検出し、役割を画面で割り当て |
| エラー処理が `alert` のみ | キャンセルまで「失敗」と表示 | 状況別のログ表示。環境非対応も起動時に警告 |

設定（ポート割り当て・最大出力・トリム等）はブラウザの localStorage に保存され、次回起動時に復元されます。

## `Connection already in progress.` が出るとき

ログに次のように出て、書き込みが 1 バイトも通らない状態です。

```
[10:45:40] 通知の購読に失敗（角度フィードバックなしで続行）: Connection already in progress.
[10:45:40] 送信エラー: Connection already in progress.
```

サービスの探索までは成功しているのに、以降の読み書きが全て弾かれています。原因は 2 つです。

**(a) GATT 接続が確立しきる前に操作を始めている**

Chrome は接続が完全に落ち着く前に `gatt.connect()` を解決させることがあります。
接続後に 0.6 秒待ち、失敗した操作は間隔を空けて最大 5 回まで再試行するようにしてあるので、
これが原因なら現在のページでは自動的に回復します（ログに「再試行 1/5」と出ます）。

**(b) 他の誰かがそのハブを掴んでいる**

こちらが本命です。同じハブへの GATT 接続は 1 つしか張れません。

1. **このページを開いた他のタブを全て閉じる** — 先に開いたタブが接続を保持し続けます。最も多い原因です
2. **LEGO 公式アプリ**など、ハブに接続する他のアプリを終了する
3. **OS の Bluetooth 設定でハブをペアリングしない** — Powered Up ハブは OS 側で「ペアリング済み」にしてはいけません。
   登録されている場合は削除してください。ブラウザのデバイス選択ダイアログからだけ接続します
4. ハブの電源を入れ直し、緑点滅の状態にしてから「再接続」ボタンを押す

接続時にハブへ機種 ID を問い合わせ、応答が返ることを確認してから使用可能にしています。
応答がない場合はこの手順をログに表示します。

## コントローラーが「Unknown Gamepad」と表示されるとき

`Unknown Gamepad (Vendor: 045e Product: 0b13)` のように表示され、`mapping` が `standard` でない場合、
ブラウザ標準のボタン番号（RT = `buttons[7]`）が当てになりません。
Xbox コントローラーでも、OS・接続方式・ファームウェアによってはトリガーが `axes[4]` / `axes[5]` に、
休止値 -1 の軸として現れます。

この場合はコントローラーのカードにある **「アクセルを学習」「ブレーキを学習」「ステアリングを学習」** を順に押してください。
3 秒間のサンプリングで、最も大きく動いた軸／ボタンを自動的に割り当てます。
休止値と可動範囲も同時に記録するので、-1 を中心とする軸でも正しく 0〜100% に正規化されます。
割り当てはブラウザに保存され、次回以降そのまま使えます。

## 接続できたのにモーターが動かないとき

ページ下部の「診断」カードで、コントローラーと切り離してハブとの通信だけを検証できます。
上から順に試すと原因が 1 つに絞れます。

**手順 1 — 「ハブ情報を要求」を押す**

ハブ名・機種 ID・ファームウェアがログに出れば、**送信も受信も成立しています**。
出ない場合は書き込みがハブに届いていないので、手順 2 へ。

**手順 2 — 「書き込み方式」を切り替える**

Windows の Chrome では `writeValueWithoutResponse` が例外も出さずに握りつぶされることがあります。
接続は正常に見え、送信カウンタも増えるのに、モーターだけが一切反応しません。
既定は確実な「応答あり (writeValue)」ですが、逆に応答ありが通らない環境もあるため、
切り替えて「ハブ情報を要求」をもう一度試してください。

**手順 3 — 「ポートスキャン」を押す**

A〜F を順に 0.6 秒ずつ +50% で回します。どのポートで何が動いたかを見て、
「ポート割り当て」を実機に合わせてください。ポート番号が違うだけなら、これで解決します。

**手順 4 — 「駆動コマンド方式」を「速度指定」に変える**

モーターによっては `WriteDirectModeData` のパワー指定を受け付けず、`StartSpeed` でしか回らないことがあります。
走行設定の「駆動コマンド方式」を切り替えて、もう一度ポートスキャンを実行してください。

**手順 5 — それでも駄目なら 16 進ログ**

「送受信パケットを 16 進数でログに出す」をオンにすると、TX/RX が全部ログに出ます。
ハブがエラーを返している場合は `ハブがエラーを返しました: command 0x81 → パラメーター値が不正` のように理由が表示されます。

### 症状から見た原因の切り分け

| 症状 | 原因 |
|---|---|
| 「送信 / エラー」の**エラー側が増える** | GATT 書き込みの失敗。書き込み方式を切り替える |
| **送信は増えるがエラーは 0、なのに無反応** | 書き込みがハブに届いていない（手順 2）か、ポート番号違い（手順 3） |
| ポート割り当ての**検出欄が全部「未接続」** | 通知が購読できていない。ハブを再起動して再接続 |
| 「安全ロック」が**未解除のまま** | アクセルが握られたままか、トリガーの button 番号が違う。「入力の割り当てと生の値を表示」で確認 |
| 画面の**アクセルのバーが動かない** | ハブ側ではなくコントローラー側の問題。button 番号を設定し直す |

## うまく動かないとき

| 症状 | 確認すること |
|---|---|
| 「Web Bluetooth が使えません」と出る | iOS では Bluefy で開いているか。PC では Chrome / Edge か |
| ポップアップにハブが出ない | ハブが**緑点滅**（アドバタイズ中）になっているか。他のアプリ（LEGO 公式アプリ等）が先に掴んでいないか |
| コントローラーが「未検出」 | ペアリング後、ページを開いた状態でボタンを 1 回押す |
| トリガーが効かない | 「アクセルを学習」「ブレーキを学習」を実行して割り当て直す |
| 前後が逆・左右が逆 | ポートの役割を「駆動（反転）」に変更、またはステアリング反転をチェック |
| 直進しているのに曲がっている | 「トリム（中央補正）」で調整するか、タイヤを直進にして「現在位置をセンターに設定」 |
| ステアリングが片側に張り付く | 「ステア最大トルク」を下げ、最大舵角をモデルに合わせて小さくする |

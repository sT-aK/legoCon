# LEGO Hub × Xbox Controller (Web Bluetooth)

純正ファームウェアのままの LEGO Powered Up ハブ（Technic Move Hub / Technic Hub / City Hub など）を、
**Xbox ワイヤレスコントローラー**で操作するための 1 ファイル完結の Web ページです。

ハブの改造もアプリのインストール（ブラウザを除く）も不要で、`index.html` を HTTPS で配信するだけで動きます。

- 実物: `index.html`（依存ライブラリなし・オフラインでも動作）
- 対象例: LEGO 42176 ポルシェ GT4 e-Performance（Technic Move Hub）— 実機で動作確認済み

---

## 仕組み

```
[Xbox Wireless Controller]
      │  Bluetooth（iOS / iPadOS / Windows / macOS が標準対応）
      ▼
[iPhone など] ── Bluefy（iOS）または Chrome / Edge（PC）
      │  ├─ 1. Gamepad API  : トリガー・スティックの値を取得（0.0〜1.0 / -1.0〜1.0）
      │  └─ 2. LWP3         : LEGO Wireless Protocol v3 のバイナリコマンドを生成
      │  Web Bluetooth API（BLE / GATT）
      ▼
[LEGO Hub（純正・未改造）]
      ├─ 駆動モーター ×2  : 前後進（逆符号）＋ 旋回（内輪のみ減速）
      └─ ステアリング     : 出力制御（舵角が読める機種では角度制御）
```

1. **Bluetooth 接続**: LEGO ハブ共通の BLE サービス UUID `00001623-1212-efde-1623-785feabcd123` で
   デバイスを絞り込み、キャラクタリスティック `...1624...` に対して読み書きします。
2. **制御ループ**: `requestAnimationFrame` で毎秒約 60 回コントローラーを読み取り、
   値が変化したときだけ LWP3 のコマンドを送信キューに積みます。

### 送信しているコマンド

| 用途 | LWP3 サブコマンド | バイト列 |
|---|---|---|
| 駆動モーター出力 | `WriteDirectModeData` (0x51) | `08 00 81 <port> 11 51 00 <power>` |
| ステアリング角度 | `GotoAbsolutePosition` (0x0D) | `0E 00 81 <port> 11 0D <angle:int32LE> <speed> <maxPower> 7E 00` |
| 角度の受信設定 | `Port Input Format Setup` | `0A 00 41 <port> 02 <delta:uint32LE> 01` |
| バッテリー通知 | `Hub Properties` | `05 00 01 06 02` |
| ハブのライト | `WriteDirectModeData` (0x51) | `08 00 81 <port> 11 51 00 <色番号>` |

## 使い方

### 1. Xbox コントローラーを接続する

iPhone / iPad の「設定」→「Bluetooth」からペアリングします。
Xbox のペアリングボタン（上面の小さなボタン）を長押しして、ロゴが速く点滅している状態で選択します。

### 2. ブラウザを用意する

| 環境 | ブラウザ |
|---|---|
| iPhone / iPad | **Bluefy – Web BLE Browser**（App Store・無料） |
| Windows / macOS / Android | Chrome または Edge |

> iOS の Safari と Chrome for iOS は Web Bluetooth に対応していないため動きません。Bluefy が必要です。

### 3. ページを公開する

Web Bluetooth は **HTTPS（または localhost）でしか動作しません**。
このリポジトリをそのまま GitHub Pages で公開するのが最短です。

1. GitHub の **Settings → Pages** を開く
2. **Source** を `Deploy from a branch`、ブランチを `main`（フォルダは `/root`）に設定
3. 数十秒後に `https://<ユーザー名>.github.io/<リポジトリ名>/` で公開されます

Netlify や Vercel にドラッグ&ドロップしても同じです。

### 4. 接続して走らせる

1. Bluefy で公開した URL を開く
2. コントローラーの**いずれかのボタンを 1 回押す**
   （ブラウザは最初の入力があるまでゲームパッドを認識しません。「検出」が緑になれば OK）
3. ハブの緑ボタンを 1 回押して**緑点滅**させる
4. ページの「LEGO Hub に接続」をタップし、ポップアップに出たハブを選択
5. **ポート割り当てを確認する** — 確認済みの機種なら自動で設定されます。
   ログの `現在の割り当て — 駆動: … / ステアリング: …` が実機と合っているか見てください。
   違っていれば「確認済みの構成を適用」か、手動で割り当て直します
6. **初回は「最大出力」を 30〜40% に下げる**
7. 「アクセルを学習」「ブレーキを学習」「ステアリングを学習」を順に実行する
   （標準マッピングとして認識されている環境では既定のままでも動きます）
8. 右トリガーで前進、左トリガーで後退、左スティックでステアリング、
   **右スティック横で旋回**、**Y ボタンでライトの切り替え**
9. モデル前後のランプを使う場合は、診断の「ライトスキャン」で該当ポートを見つけ、
   「ポート割り当て」で「ライト」に設定する

前に進まず車体が**その場で回る**場合は、駆動 2 つのうち片方を「駆動（反転）」に変えてください
（左右のモーターが対向して組まれている場合に必要です）。
まっすぐ走るが**前後が逆**の場合は、走行設定の「駆動の前後を反転」を入れてください。

## 旋回（内輪を減速）

左右の駆動輪を**同じ向きに回したまま、内側になる輪だけ出力を落として**弧を描いて曲がります。
逆回転させないので駆動系とタイヤへの負担が軽く、動きも自然です。

倒し込み量に応じて内輪が落ちていき、目一杯で**半分**になります。

| 操作 | ポート 50（反転） | ポート 51 |
|---|---|---|
| 前進のみ | -70 | +70 |
| 前進 + 旋回右（半分） | -70 | **+53** |
| 前進 + 旋回右（全開） | -70 | **+35** |
| 旋回のみ 右 | -50 | +25 |

符号が逆なのは左右のモーターが対向して組まれているためで、**どちらも物理的には前向き**です。

既定では**右スティックの横方向**に割り当てられています（キーボードでは `Q` / `E`）。
効かない場合はコントローラーの「旋回を学習」を実行してください。曲がる向きが逆なら
走行設定の「旋回の向きを反転」で直せます。

アクセルを踏んでいないときは、**「旋回だけのときの速度」**（既定 50%）で前進しながら曲がります。

### 曲がりが緩いとき

**「旋回時にステアリングも切る」**（既定でオン）を有効にすると、旋回と同じ向きに舵を切ります。
前輪が直進を向いたままだと横滑りを拒んで抵抗になるため、これを入れると格段に曲がりやすくなります。

床の摩擦が高いほど曲がりにくくなります。フローリングやタイルの上が最も曲がりやすく、
カーペットの上では鈍くなります。

## ライト

**コントローラーのボタン（既定は Y）で、ハブ内蔵 LED とモデルのランプをまとめて
消灯／点灯できます。** ボタンの割り当てはコントローラーカードの「ライトを学習」で変更できます。

### ハブ内蔵の RGB LED

**消灯**のほか、白・赤・緑・青・黄・橙・紫を選べます。選んだ色は接続時にも自動で適用されます。
既定は「そのまま」で、この場合はハブの LED には一切コマンドを送りません。

色番号指定（`mode 0`、`0` が消灯）で送ります。ポートは検出結果から自動で判別します
（型 `0x0017` = RGB Light。実機の Technic Move Hub ではポート 63）。

```
08 00 81 <ポート> 11 51 00 <色番号>
```

> 消灯するとハブの接続状態が光で分からなくなります。ページの「状態」表示で確認してください。

### モデル前後のランプ

ハブ内蔵の LED とは**別のポート**に繋がっています。どのポートかは機種と組み方によるため、
**実機で光らせて確かめます**。

1. 診断の **「ライトスキャン」** を押す — 駆動・ステアリング・センサー以外のポートを
   1 つずつ 1 秒間フル点灯します
2. **ランプが光ったポート**を「ポート割り当て」で **「ライト」** に設定する
3. 以後、コントローラーのボタンでまとめて点灯／消灯できます

明るさは「モデルのランプの明るさ」で調整できます（既定 100%）。

```
08 00 81 <ポート> 11 51 00 <明るさ 0〜100>
```

ライトは**緊急停止では消えません**。停止はモーターに対する操作なので、
点灯状態はそのまま保たれます。

## このページの安全設計

模型とはいえモーターは指を挟むだけの力があり、暴走すると止められません。次の保護を入れてあります。

- **安全ロック**: 接続時にアクセルが握られたままなら、いったん離すまで出力しません。
- **緊急停止**: 画面の STOP ボタン、コントローラーの **B ボタン**、キーボードの **Space**。
- **自動停止**: ハブとの切断時、コントローラーの切断時、ページを閉じた・バックグラウンドに回った時。
- **ステアリングのトルク制限**: 既定は「出力指定」で、最大トルクを制限したうえ、
  **切り終えて 0.4 秒経つと保持トルクを半分に落とします**。メカストップに全力を掛け続けないため、
  発熱とギアへの負荷を抑えられます。舵角フィードバックが読める機種では「角度指定」に
  切り替えると、目標角へ動かす方式になり端当て自体を避けられます。
- **最大出力の制限**: 既定は 70%。慣れるまで下げておくのがおすすめです。

## 元のサンプルコードから変更した点

よく出回っている「60fps で `sendMotorPower()` を呼ぶだけ」の実装には、実機で困る問題がいくつかあります。

| 問題 | 起きること | このページでの対処 |
|---|---|---|
| BLE 書き込みを `await` せず並行実行 | `GATT operation already in progress` 例外が多発 | 送信キューで直列化。同じポートの古い指示は新しい値で上書き |
| 60fps でそのまま送信 | BLE の接続間隔を超えて詰まり、遅延・切断 | ポートごとに最短 35ms のレート制限 |
| ステアリングを全力で駆動 | 舵角の端でモーターが停動し続け、発熱・ギア破損 | トルク上限を設定。舵角が読める機種では `GotoAbsolutePosition` による角度制御 |
| 角度が読めないまま角度指令を送る | 機種によってはハブが接続ごと切ってしまう | フィードバックを確認できたときだけ角度指令を使う |
| 「変化が 3 以上なら送る」判定 | トリガーを離しても 0 が送られず微速で走り続ける | 0 は必ず即時送信 |
| `writeValueWithoutResponse` 決め打ち | 非対応の特性で例外 | `properties` を見て `writeValue` に自動フォールバック |
| `gamepads[0]` 決め打ち | iOS では index が 0 とは限らず、null 穴もある | 接続中のパッドを走査して選択 |
| ボタン番号の決め打ち | 標準マッピングと認識されない環境ではトリガーが別の軸に出る | 実際に動かして割り当てを学習する機能 |
| 接続直後にすぐ GATT 操作 | `Connection already in progress` で全ての読み書きが失敗する | 一時エラーは間隔を空けて再試行。機種 ID の応答で疎通を確認 |
| 切断された後もリトライを続ける | `GATT Server is disconnected` は何度試しても成功しない | 切断と一時エラーを区別し、切断時は接続からやり直す |
| 接続処理の二重起動 | 自動再接続と手動接続が互いを切断し合い、切断が止まらなくなる | 接続処理は同時に 1 つだけに制限 |
| デッドゾーンなし | スティックのドリフトで直進しない | デッドゾーン + 感度カーブ（EXPO）を調整可能 |
| ポート番号がハードコード | 機種や組み方が違うと動かない | 接続時にモーターを自動検出し、役割を画面で割り当て |
| エラー処理が `alert` のみ | キャンセルまで「失敗」と表示 | 状況別のログ表示。環境非対応も起動時に警告 |

設定（ポート割り当て・最大出力・トリム等）はブラウザの localStorage に保存され、次回起動時に復元されます。

### ハブが返すエラーコード

`ハブがエラーを返しました: command 0x81 → …` の数値は LWP3 のジェネリックエラーです。

| コード | 意味 |
|---|---|
| 0x01 / 0x02 | ACK / MACK |
| 0x03 | バッファオーバーフロー |
| 0x04 | タイムアウト |
| 0x05 | コマンド未対応 |
| 0x06 | パラメーターが不正（存在しないポート、非対応の指令など） |
| 0x07 | 過電流 |
| 0x08 | 内部エラー |

ステアリングの角度指令（`GotoAbsolutePosition`）の直後に `0x81 → 0x06` が返った場合は、
そのモーターが角度指定に対応していないと判断して、**自動的に「出力指定」へ切り替えます**。

## ポート番号は機種によって違う

外部ポート A〜D を 0〜3 と決め打ちにはできません。ハブの**内蔵モーターやセンサーは
50 番以降**に並び、その配置は機種ごとに異なります。

実機の Technic Move Hub（機種 ID `0x84`、42176 ポルシェ）が報告してきた構成は次のとおりでした。

| ポート | 型 | 確認結果 |
|---|---|---|
| **50, 51** | `0x0056` ×2 | 指令を受理。**左右の車輪が回転** → 駆動（左右が対向して組まれているため 50 は反転） |
| **52** | `0x0057` | 指令を受理。**ステアリングが左右に振れる** → ステアリング |
| 53, 54 | `0x0058`, `0x0059` | `0x81 → パラメーターが不正` で**拒否**（モーターではない） |
| 55〜58 | `0x003c`, `0x0039`, `0x003a`, `0x003b` | 温度・加速度・ジャイロ・傾き |
| 60 | `0x0014` | 電圧 |
| 63 | `0x0017` | RGB LED |

外部ポート A〜D は 1 つも報告されません。このハブでは、これらの内蔵デバイスが操作対象です。

そのためページは次のように動きます。

- ポート一覧は**ハブが報告してきたポートだけ**を表示する（存在しないポートは出さない）
- 別機種向けの割り当てが残っていたら、接続時に自動で解除する
- 存在しないポートへはコマンドを送らない（送っても `0x81 → パラメーターが不正` で弾かれるだけ）
- 「ポートスキャン」は**検出されたポートのうち、モーターでないと分かっているもの
  （電圧・電流・各種センサー・LED）を除いて**順に回し、ハブが受理したか拒否したかを
  自動で判定して最後に要約する

上の構成は実機で確認済みなので、**機種 ID `0x84` のハブでポート 50/51/52 が検出され、
まだ何も割り当てていない場合は自動で設定されます**（手動で設定した内容は上書きしません）。

42176 は左右のモーターが**対向して組まれている**ため、片方だけ回転方向を反転させないと
その場で回ってしまいます。自動設定では 51 = 駆動、**50 = 駆動（反転）** を割り当てます。
トリガーを引いて後進する場合は、走行設定の **「駆動の前後を反転」** を入れてください
（両方の向きがまとめて反転します）。

未知の機種では、ポートスキャンで受理されたポートのうちどれが駆動でどれがステアリングかを、
実機の動きを見て割り当ててください。

### 誤ったポートに割り当ててしまったとき

**モーターでないポートにモーター指令を送ると、ハブが接続を切ることがあります。**
操作した瞬間に切断される場合は、まずポート割り当てを疑ってください。

- 確認済みの構成から外れたポートが割り当てられていると、接続時に警告が出ます
- ポートが指令を拒否したら、**そのポートを自動的に送信対象から外します**
  （拒否されたポートに送り続けると接続が切れるため）
- **「確認済みの構成を適用」** ボタンで、その機種の正しい割り当てに一括で戻せます

以前のセッションの割り当てはブラウザに保存されるので、実験中に設定した値が残ることがあります。
`現在の割り当て — 駆動: … / ステアリング: …` の行で、毎回の接続時に確認できます。

## デバイス選択の画面が出ない・すぐ失敗するとき

`requestDevice()` の受け付け方はブラウザ差が大きく、特に iOS の Bluefy では
サービス UUID による絞り込みが通らないことがあります。そのため、次の順で自動的に試します。

1. **サービス UUID で絞り込み** — `filters: [{ services: [00001623-…] }]`。ハブだけが一覧に出ます
2. **名前で絞り込み** — `namePrefix` が `Technic` / `LEGO` / `Move` / `Hub` のもの
3. **すべてのデバイスを表示** — 絞り込みなし。一覧から手動で `Technic Move` を選びます

通った方法はそのセッションの既定になります。ログには試した方法と、失敗した場合は
エラーの種別・コード・メッセージが全て出ます（`NotFoundError / 2` のような形）。

> ブラウザによっては、続けて `requestDevice()` を呼ぶのにボタンの押し直しが必要です。
> 「デバイスを選択できませんでした」と出たら、もう一度ボタンを押してください。
> 2 回目は次の検索方法から始まります。

## edge://bluetooth-internals で切り分ける

ページのコードを完全に排除して、ハブと OS の間だけを検証できます。
Edge なら `edge://bluetooth-internals/#devices`、Chrome なら `chrome://bluetooth-internals/#devices` を開き、
**Start Discovery** → `Technic Move` の **Connect** → サービス一覧を確認します。

正常なハブなら次のように見えます。

```
GATT Connected: Connected
Services: 00001623-1212-efde-1623-785feabcd123, 00001800-…, 00001801-…, f000ffc0-…
  00001623-1212-efde-1623-785feabcd123
    00001624-1212-efde-1623-785feabcd123
      Properties: Write Without Response, Write, Notify
Manufacturer Data: 0x0397 0x008402ff0100
```

- `00001623` / `00001624` があり、`Write` と `Notify` が立っていれば、このページの前提どおりです
- `f000ffc0-0451-…` は TI 製チップのファームウェア更新サービスで、LEGO ハブでは正常な構成です
- Manufacturer Data の `0x0397` は LEGO 社の Company ID、続く 2 バイト目 `84` が**機種 ID（Technic Move Hub）**です

> **重要**: この画面で接続したままにすると、ハブはその接続に占有されます。
> ページを試す前に必ず **Disconnect**（または Forget）を押し、bluetooth-internals のタブを閉じてください。
> 押し忘れると、ページ側は `Connection already in progress` や接続直後の切断として現れます。

## 通知が受け取れないとき（送信のみモード）

`startNotifications` に失敗しても、**モーターを動かすだけなら書き込みだけで足ります**。
通知が必要なのはポートの自動検出・バッテリー表示・舵角フィードバックだけです。

そのため、書き込みが通っていて応答だけが来ない場合は、状態表示を **「接続中（送信のみ）」** にして走行可能なまま接続します。
この状態では次のようにしてください。

- **ポート割り当て**: 自動検出できないので、診断の「ポートスキャン」でどのポートが動くかを実機で確認して設定する
- **ステアリング**: 舵角が読めないので、走行設定の制御方式を「出力指定」に切り替える。
  「ステア最大トルク」は低め（30〜50%）にして、端当ての負荷を抑える

## 接続はできるのに数秒で切れるとき

ページは**接続時に 2 つのコマンドしか送りません**（機種 ID の問い合わせと、バッテリー通知の有効化）。
モーターへの指令も舵角の購読も、実際にコントローラーを操作するまで送りません。
接続直後に次のログが出ます。

```
操作するまでコマンドは送りません。ここで切断される場合、原因は送信内容ではありません。
```

この状態で切断されるなら、原因はページが送る内容ではありません。次を確認してください。

- **同じ端末に繋いでいる他の Bluetooth 機器を切る** — 特に Xbox コントローラー。
  1 つの無線を複数の接続で分け合うため、混み合うと BLE のリンクが不安定になります。
  切り分けとして、**コントローラーの電源を切った状態でハブだけに接続**してみてください
- **LEGO 公式アプリを完全終了する** — iOS ではバックグラウンドのアプリが既知のハブに
  自動再接続します。タスクスイッチャーから上スワイプで終了してください
- ハブの電池残量、端末との距離（30cm 以内）、モーターに負荷がかかっていないか

リンクがどうしても不安定な環境では、接続カードの **「切れたら自動で再接続し続ける」** を
有効にしてください。「切断」ボタンを押すまで再接続を繰り返すので、数秒の切断があっても
操作を続けられます。切断回数と接続が持った秒数も表示されるので、安定度の目安になります。

> 再接続後は安全ロックが再びかかります。アクセルを握ったままだと出力されないので、
> 一度離してから操作してください（切断中に握っていた分がそのまま出るのを防ぐためです）。

操作した瞬間に切れるなら、その指令がそのハブに受け入れられていません。
ログの直前の行（どのポートへ何を送ったか）と、`ハブがエラーを返しました` の行を見てください。

## `GATT Server is disconnected` が出るとき

```
[11:07:38] 接続中: Technic Move
[11:07:39] ハブとの接続が切れました
[11:07:39] サービス取得: … GATT Server is disconnected. Cannot retrieve services.
```

`gatt.connect()` は成功したのに、その直後に**ハブ側から接続を切られています**。
一度切れた GATT サーバーに対しては、同じ操作を何度繰り返しても成功しません。接続からやり直す必要があります。

現在のページは次のように動きます。

- 接続後に待たず、**サービス探索と通知購読をすぐ実行する**
  （ハブは接続後に無操作の時間があると切ってしまうことがあります）
- セットアップ中に切られた場合は、**接続の最初からやり直す**（最大 4 回）
- 使用中に切れた場合は、**自動で 2 回まで再接続する**
- それでも駄目なら、下記の確認手順をログに表示する

原因はほぼ OS 側との競合です。

1. **Windows の「設定 → Bluetooth とデバイス」にハブがあれば「デバイスの削除」を実行する**
   Powered Up ハブは OS に登録してはいけません。ブラウザの選択画面からだけ接続します
2. ハブの電源を切り、10 秒待ってから入れ直す
3. 緑の点滅を確認したら、すぐに接続する。**点滅が終わって待ち受けが切れると、接続してもすぐ落ちます**
4. ハブの電池残量を確認する（電圧不足でも接続直後に落ちます）

> ブラウザのデバイス選択ダイアログに出る「ペアリング」は**押して構いません**。
> これは「このサイトにこのデバイスへのアクセスを許可する」という意味で、Web Bluetooth の必須手順です。
> 避けるべきなのは OS の Bluetooth 設定にハブを登録することだけです。

## `Connection already in progress.` が出るとき

ログに次のように出て、書き込みが 1 バイトも通らない状態です。

```
[10:45:40] 通知の購読に失敗（角度フィードバックなしで続行）: Connection already in progress.
[10:45:40] 送信エラー: Connection already in progress.
```

サービスの探索までは成功しているのに、以降の読み書きが全て弾かれています。原因は 2 つです。

**(a) GATT 接続が確立しきる前に操作を始めている**

Chrome は接続が完全に落ち着く前に `gatt.connect()` を解決させることがあります。
接続後に 0.6 秒待ち、失敗した操作は間隔を空けて最大 5 回まで再試行するようにしてあるので、
これが原因なら現在のページでは自動的に回復します（ログに「再試行 1/5」と出ます）。

**(b) 他の誰かがそのハブを掴んでいる**

こちらが本命です。同じハブへの GATT 接続は 1 つしか張れません。

1. **このページを開いた他のタブを全て閉じる** — 先に開いたタブが接続を保持し続けます。最も多い原因です
2. **LEGO 公式アプリ**など、ハブに接続する他のアプリを終了する
3. **OS の Bluetooth 設定でハブをペアリングしない** — Powered Up ハブは OS 側で「ペアリング済み」にしてはいけません。
   登録されている場合は削除してください。ブラウザのデバイス選択ダイアログからだけ接続します
4. ハブの電源を入れ直し、緑点滅の状態にしてから「再接続」ボタンを押す

接続時にハブへ機種 ID を問い合わせ、応答が返ることを確認してから使用可能にしています。
応答がない場合はこの手順をログに表示します。

## コントローラーが「Unknown Gamepad」と表示されるとき

`Unknown Gamepad (Vendor: 045e Product: 0b13)` のように表示され、`mapping` が `standard` でない場合、
ブラウザ標準のボタン番号（RT = `buttons[7]`）が当てになりません。
Xbox コントローラーでも、OS・接続方式・ファームウェアによってはトリガーが `axes[4]` / `axes[5]` に、
休止値 -1 の軸として現れます。

この場合はコントローラーのカードにある **「アクセルを学習」「ブレーキを学習」「ステアリングを学習」** を順に押してください。
3 秒間のサンプリングで、最も大きく動いた軸／ボタンを自動的に割り当てます。
休止値と可動範囲も同時に記録するので、-1 を中心とする軸でも正しく 0〜100% に正規化されます。
割り当てはブラウザに保存され、次回以降そのまま使えます。

## 接続できたのにモーターが動かないとき

ページ下部の「診断」カードで、コントローラーと切り離してハブとの通信だけを検証できます。
上から順に試すと原因が 1 つに絞れます。

**手順 1 — 「ハブ情報を要求」を押す**

ハブ名・機種 ID・ファームウェアがログに出れば、**送信も受信も成立しています**。
出ない場合は書き込みがハブに届いていないので、手順 2 へ。

**手順 2 — 「書き込み方式」を切り替える**

Windows の Chrome では `writeValueWithoutResponse` が例外も出さずに握りつぶされることがあります。
接続は正常に見え、送信カウンタも増えるのに、モーターだけが一切反応しません。
既定は確実な「応答あり (writeValue)」ですが、逆に応答ありが通らない環境もあるため、
切り替えて「ハブ情報を要求」をもう一度試してください。

**手順 3 — 「ポートスキャン」を押す**

A〜F を順に 0.6 秒ずつ +50% で回します。どのポートで何が動いたかを見て、
「ポート割り当て」を実機に合わせてください。ポート番号が違うだけなら、これで解決します。

**手順 4 — 「駆動コマンド方式」を「速度指定」に変える**

モーターによっては `WriteDirectModeData` のパワー指定を受け付けず、`StartSpeed` でしか回らないことがあります。
走行設定の「駆動コマンド方式」を切り替えて、もう一度ポートスキャンを実行してください。

**手順 5 — それでも駄目なら 16 進ログ**

「送受信パケットを 16 進数でログに出す」をオンにすると、TX/RX が全部ログに出ます。
ハブがエラーを返している場合は `ハブがエラーを返しました: command 0x81 → パラメーター値が不正` のように理由が表示されます。

### 症状から見た原因の切り分け

| 症状 | 原因 |
|---|---|
| 「送信 / エラー」の**エラー側が増える** | GATT 書き込みの失敗。書き込み方式を切り替える |
| **送信は増えるがエラーは 0、なのに無反応** | 書き込みがハブに届いていない（手順 2）か、ポート番号違い（手順 3） |
| ポート割り当ての**検出欄が全部「未接続」** | 通知が購読できていない。ハブを再起動して再接続 |
| 「安全ロック」が**未解除のまま** | アクセルが握られたままか、トリガーの button 番号が違う。「入力の割り当てと生の値を表示」で確認 |
| 画面の**アクセルのバーが動かない** | ハブ側ではなくコントローラー側の問題。button 番号を設定し直す |

## うまく動かないとき

| 症状 | 確認すること |
|---|---|
| 「Web Bluetooth が使えません」と出る | iOS では Bluefy で開いているか。PC では Chrome / Edge か |
| ポップアップにハブが出ない | ハブが**緑点滅**（アドバタイズ中）になっているか。他のアプリ（LEGO 公式アプリ等）が先に掴んでいないか |
| コントローラーが「未検出」 | ペアリング後、ページを開いた状態でボタンを 1 回押す |
| トリガーが効かない | 「アクセルを学習」「ブレーキを学習」を実行して割り当て直す |
| 前後が逆・左右が逆 | ポートの役割を「駆動（反転）」に変更、またはステアリング反転をチェック |
| 直進しているのに曲がっている | 「トリム（中央補正）」で調整するか、タイヤを直進にして「現在位置をセンターに設定」 |
| ステアリングが片側に張り付く | 「ステア最大トルク」を下げ、最大舵角をモデルに合わせて小さくする |
